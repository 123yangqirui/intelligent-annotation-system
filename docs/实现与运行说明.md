## 5. 使用流程

1. 管理员创建普通账号；项目负责人添加 annotator 或 reviewer 成员。
2. 创建文本分类或图像检测项目。
3. 创建标签规范并发布。已发布规范的新规则通过新版本加入。
4. 手工建立数据版本并录入文本，或上传 CSV/JSONL/图片/ZIP。
5. 导入错误通过后台任务查看；有部分错误的版本需确认有效部分后发布。
6. 已发布数据集合不追加；复制为新版本后可调整 train/val/test 划分。
7. 打开标注工作台，保存草稿并提交。图片先选择类别，再画框；调整模式用于移动缩放，平移模式移动画布。
8. 审核员接受、退回或修正并接受。原始提交者与审核者不同，除非项目显式允许自审。
9. 导出已审核版本，等待后台打包后下载 ZIP。包含标签映射和 manifest。

当前前端手动保存；提交或离开标注页面会保存已修改草稿。不是定时自动保存；网络失败或版本冲突时保留编辑状态并显示错误。

## 6. 模型与大模型 API

管理中心先配置供应商，再授权给项目，最后注册模型规格。文本 LLM 使用兼容 `/chat/completions` 的服务，要求返回 `{ "label_id": "规范中的ID" }`，服务端仍校验结果。

密钥用 Fernet 加密，主密钥在 backend/.env；前端和普通响应不返回密钥。只允许配置 `PROVIDER_ALLOWED_HOSTS` 中的地址。模型接口差异需要适配，不保证所有“兼容”服务都支持同一参数。

预算目前按 token 管理，不提供未经核验的金额账单。调用前事务预留，调用后按 usage 结算；超时或未知 usage 保留预留，显示 usage_unknown。管理员可在管理中心的“未知用量对账”填写供应商确认的实际 token，用 `/api/v1/admin/model-calls/{call_id}/reconcile?total_tokens=...` 结算并释放对应预留。每次对账记录操作者，已结算调用不能重复结算；不会自动猜测超时费用为零。

非语言模型使用 `/health` 与 `/predict` 协议。请求包含样本和项目标签，返回 content 与 signals；参考真值不传入模型。BERT 需要已训练分类头与标签映射；YOLO 只能检测检查点支持的类别。空预测不等于人工确认空图。

基础质量策略全部进入人工审核，并记录低分/空预测等复核原因；不声称自报 confidence 是正确概率。训练后可以比较质量与成本。

## 7. 一键模型部署

支持 bert、yolo、qwen、deepseek 四种固定模板，启动过程保存 preparing/starting/warming/ready/failed/stopped 状态。每个检查点创建独立规格，避免换权重后沿用旧模型版本。

本机没有 Docker，当前未运行 Docker 模型实例。Docker 可用时，独立 deployment Worker 执行构建、启动和健康检查；普通 API 不挂 Docker socket。管理中心的失败消息会明确提示缺失运行条件。

语言模型模板使用 vLLM，要求支持的 Linux GPU、驱动与权重。模板中的镜像版本需在实际实验环境验证，不是“任意机器任意模型”部署保证。

训练输出会注册 candidate 模型；检查点使用 `trained:<任务UUID>`，部署只允许引用系统训练目录中的产物，不接受任意宿主路径。

## 8. 训练与评估

训练需要 train 和 val 两种划分的人工审核快照。参数包括 checkpoint、epochs、batch_size、learning_rate、seed、max_length/image_size，未知参数被拒绝。测试集不加入训练快照。

本机可建立独立训练解释器：

```bash
cd /Users/bytedance/learn/futureproject/backend
uv venv ../.local/training-venv
uv pip install --python ../.local/training-venv/bin/python -r ../model_services/training-requirements.txt
```

在 backend/.env 设置 `TRAINING_PYTHON` 为该解释器绝对路径，然后重启 training Worker。本轮没有下载这些大型 ML 依赖或训练权重。

分类指标为 Accuracy、Macro-F1 和混淆矩阵。检测提供 IoU 0.5 匹配 precision/recall，以及有逐框分数时的 101 点插值 mAP50/mAP50:95；当前 AP 没有 COCO area/maxDets 分层，不与完整 COCO 指标冒充等价。无逐框分数时 mAP 标为不可计算。

评估真值由导入用途 evaluation 写入独立表，仅评估任务读取。普通数据详情和预测请求不返回真值。


## 12. 实现决策与当前边界

- API 使用同步 SQLAlchemy 和同步端点，由 FastAPI 的线程执行；Worker 复用同一业务校验。相较初稿的 AsyncSession，这降低当前同步工具链复杂度，不在 async 端点里阻塞执行数据库查询。
- 数据版本表直接表示固定集合，未额外建立 datasets 命名容器表；保留父版本和成员关系。
- 项目 owner 可审核他人，reviewer 可审核与修正，annotator 可编辑提交；自审受项目开关约束。
- 默认人工审核，未开放机器结果自动冒充人工接受。
- 基础功能真实运行；真实模型质量、完整 GPU 训练和 Docker 平台验证需要实际资源。
- Agent 已接入预测、审核快照导出与汇总工具，采用独立队列和持久执行记录；真实 Claude 规划需配置 API 凭证。

## 13. 零基础首次练习

1. 打开 Web 工作空间并用本机管理员登录。先进入“连接检查”，确认前端可以访问 API。
2. 打开“客服分类 · 示例”，查看项目中的标签规范、数据版本与样本列表。选一条文本，在工作台选择类别，保存草稿、提交审核并接受。
3. 打开“图像工作台 · 合成示例”，选择一个类别，画框；切到“选择 / 调整”移动或缩放框，保存并提交审核。已接受样本再次修改后要重新审核。
4. 在项目中创建导出任务，到任务列表等待成功后下载。API 接收请求后，真正的打包工作由 Worker 完成，因此 Worker 和派发进程也要运行。
5. 最后查看“管理中心”的用户、模型、供应商、部署与系统状态。基础练习不需要 API Key。准备好真实模型资源后，再按第 6–8 节配置预标注、部署和训练。

推荐阅读顺序为本说明第 2、4、5 节，再阅读 `backend/app/models.py` 中的项目与成员表、`backend/app/api.py` 中的项目接口，以及 `frontend/src/views/ProjectsView.vue`。先理解“页面发请求 → 后端检查身份与参数 → 数据库保存 → 返回结果 → 页面更新”，再学习队列与模型。
